该仓库采用 **Hugo** 静态站点生成器作为核心配置系统，通过单一的 `config.toml` 文件管理全局运行时配置。

### 1. 配置架构与加载机制
- **单一配置文件**：项目根目录下的 `config.toml` 是唯一的配置入口。Hugo 在构建时自动读取该文件，解析 TOML 格式的配置项。
- **配置层级**：
  - **基础配置**：包括 `baseURL`（站点根地址）、`languageCode`（语言区域）、`title`（站点标题）。
  - **主题配置**：通过 `theme` 字段指定使用 `hugo-bearblog` 主题，主题的默认行为受此控制。
  - **参数扩展**：预留了 `[params]` 块用于自定义参数（如 `customCSS`），目前处于注释状态，表明配置具有可扩展性但当前保持极简。

### 2. 关键配置项说明
- **baseURL**: `https://fb.cdnn1.com/` —— 决定了所有相对链接的生成基准，同时与根目录下的 `CNAME` 文件（内容为 `fb.cdnn1.com`）配合，用于 GitHub Pages 或类似托管服务的域名绑定。
- **languageCode**: `zh-CN` —— 设定站点默认语言为简体中文，影响 HTML 的 `lang` 属性及 SEO 元数据。
- **theme**: `hugo-bearblog` —— 指定视觉呈现层，该主题通常自带响应式设计和深色模式支持（见 `public/index.html` 中的 CSS 变量定义）。

### 3. 开发者规范
- **修改流程**：任何站点级别的变更（如更换域名、修改标题）应直接编辑 `config.toml`。修改后需重新运行 `hugo` 命令生成 `public/` 目录下的静态文件。
- **环境隔离**：当前未发现 `.env` 或多环境配置文件（如 `config.production.toml`）。若需区分开发/生产环境，建议利用 Hugo 的环境配置特性（例如创建 `config/` 目录并按环境拆分文件）。
- **内容同步**：首页内容主要由 `index.md` 驱动，而非硬编码在模板中。更新下载链接或公告时，应优先修改 `index.md`，确保内容与配置解耦。
